## 1. 論文の手法

### 1.1 ねらい
連合学習（各クライアントがデータを手元に置いたまま、モデルの更新だけをサーバに送って平均する学習）で大規模言語モデルを微調整すると、毎ラウンドの送信量が大きくなります。FedTT は、送るパラメータそのものを小さくすることで、これを減らします。

- **FedTT**：元のモデルは凍結し、各ブロックにアダプタ（小さな追加の層）を入れて、それだけを学習します。アダプタの重み行列をテンソルトレイン（TT）分解の形で持ち、TT の「コア」と呼ばれる小さな 3 階テンソルだけを学習・送信します。分類ヘッドの 768×768 の層も TT にします。
- **FedTT+**：さらに、毎ラウンド、各 TT 層のコアのうち 3 つ {G_1, G_r, G_J} だけを学習・送信します（r はラウンドごとに 2, 3, …, J−1 を巡回）。残りのコアは凍結され、全クライアントで同じ値のままです。送信量がさらに減り、データの不均一性にも強くなる、というのが論文の主張です。

### 1.2 テンソルトレイン（TT）分解
重み W ∈ R^{P×Q} を、要素の数が同じテンソル R^{k_1×…×k_J}（k_1⋯k_J = P·Q）に並べ直し、J 個のコア G_j ∈ R^{r_{j−1}×k_j×r_j}（r_0 = r_J = 1）の積で表します（論文の式 (1)）。

- 768×64 のアダプタの下向きの層は [8, 8, 12, 8, 8]（入力側 8·8·12 = 768、出力側 8·8 = 64）、ランク 5（表 10・11）。
- コアの要素数は 1·8·5 + 5·8·5 + 5·12·5 + 5·8·5 + 5·8·1 = 40 + 200 + 300 + 200 + 40 = **780**。密な行列（49,152）の約 1.6 % です。
- 順伝播では W を作らず、入力の活性をコアと 1 つずつ縮約します（「the tensor factors are directly contracted with the vector of activation values」）。

### 1.3 モデルの中での位置（図 1）
- 各ブロックの注意の後ろと MLP の後ろに 1 つずつ、アダプタ h → h + up(act(down(h))) を入れます。down は 768 → 64、up は 64 → 768 で、どちらも TT 層です。
- 分類ヘッドの 768×768 の層を TT 層（[12, 8, 8, 8, 8, 12]）にし、最後の 768×C の層は密な層のまま学習します。
- 元のモデル（LayerNorm を含む）は学習しません。

### 1.4 Algorithm 1（FedTT）と Algorithm 2（FedTT+）
各ラウンド t で：
1. 選ばれたクライアントが、サーバからグローバルな学習パラメータ w^(t) を受け取る。
2. 各クライアントが手元のデータで K 回のローカル更新（AdamW）をする。
3. 更新したパラメータをサーバに送る。FedTT は全部、FedTT+ は各 TT 層の {G_1, G_r, G_J} と分類ヘッドだけ。
4. サーバは届いたものを平均し（w^(t+1) = (1/N) Σ w_i）、全クライアントに配る。

cross-silo（クライアントが少ない）では毎ラウンド全員が参加し、大規模 cross-device（LSCD）では毎ラウンド一部のクライアントを無作為に選びます。

**擬似コードと本文の食い違い（FedTT+ の r の選び方）**
- 擬似コードの 3 行目は「mod(t, J−2) = r−1」です。そのまま読むと r ∈ {1, …, J−2} で、G_{J−1} は一度も学習されません。

- 既定は本文どおり（`plus_schedule="text"`：r = 2, 3, …, J−1, 2, … と巡回）にしました。擬似コードどおりの読み方も `plus_schedule="literal"` で回せます。

## 5. 結果：表 1 の MRPC

**設定**
- DeBERTa-base、5 クライアントの IID 分割（cross-silo、毎ラウンド全員）、1 ローカルエポック、100 ラウンド。
- 学習率 {5e-3, 1e-3, 5e-4, 1e-4} × バッチ {16, 32} の 8 通りを、FedTT・FedTT+ それぞれで回した（付録 A.3 のグリッド）。シードは 0 のみ。
- 指標は GLUE の検証データ（408 件）の F1。論文と同じく、各ランのラウンド中の最高値をとり、グリッドの中で最大のものを報告する。

**結論：FedTT・FedTT+ とも、論文の値を 1 点以内で再現した（シード 1 つ）。**

| 手法 | 本再現（グリッドの最大） | そのときの学習率・バッチ（ラウンド） | 論文（表 1） | 差 | 1 ラウンドの送信量（1 クライアント） |
|---|---|---|---|---|---|
| FedTT | 92.50 | 1e-3・32（64 ラウンド目） | 92.68 | −0.18 | 236.9 KB |
| FedTT+ | 93.24 | 5e-3・16（87 ラウンド目） | 92.60 | +0.64 | 71.3 KB |

全 16 本（最高 F1 / held-out で最高のラウンドの F1 / 最終ラウンドの F1）：

| 学習率 | バッチ | FedTT | FedTT+ |
|---|---|---|---|
| 5e-3 | 16 | 90.69 / 90.21 / 90.16 | **93.24** / 92.44 / 92.12 |
| 5e-3 | 32 | 92.15 / 90.66 / 89.95 | 92.57 / 91.59 / 91.72 |
| 1e-3 | 16 | 92.33 / 91.36 / 91.22 | 89.93 / 89.93 / 89.81 |
| 1e-3 | 32 | **92.50** / 92.14 / 91.85 | 88.00 / 88.00 / 88.00 |
| 5e-4 | 16 | 91.83 / 91.00 / 90.69 | 85.90 / 85.80 / 85.76 |
| 5e-4 | 32 | 91.00 / 90.66 / 90.66 | 84.16 / 83.84 / 84.08 |
| 1e-4 | 16 | 85.00 / 84.54 / 85.00 | 81.22 / 81.22 / 81.22 |
| 1e-4 | 32 | 83.15 / 83.12 / 83.12 | 81.22 / 81.22 / 81.22 |

81.22 は、いつも「同じ意味」と答えたときの F1 です（検証データの 68 % が正例）。この値のままのランは、何も学習できていません。

**わかったこと**
1. **論文との差はどちらも 1 点未満**（FedTT −0.18、FedTT+ +0.64）。
   - MRPC の検証データは 408 件と小さく、F1 が 92 前後のとき、1 件の答えが変わるだけで F1 が 0.15〜0.2 点動く。FedTT の差はおよそ 1 件分、FedTT+ の差は 3〜4 件分。
   - シード 1 つなので、FedTT+ が FedTT を上回ったとまでは言えない。論文でも両者の差は 0.08 点。
2. **FedTT+ は FedTT より大きい学習率が必要**。
   - FedTT は学習率 5e-4〜5e-3 のどこでも 90.7〜92.5 と安定している。
   - FedTT+ が論文の値に届くのは 5e-3 のときだけ。1e-3 では 88〜90、1e-4 では 100 ラウンドの間まったく学習しない。
   - 論文はグリッドの最大値しか載せていないので、この違いは論文からは読み取れない。
   - 理由（推測）：FedTT+ は 1 ラウンドに 5 つのコアのうち 3 つしか学習しない。小さな乱数から始めたコアどうしの積なので、学習の立ち上がりが遅い。実際、学習率 1e-3・バッチ 32 では、最初の約 30 ラウンドが 81.22 のままだった。
   - FedTT+ を比較手法として使うときは、学習率 5e-3 を含めて調整しないと、本来より 3〜5 点低く出る。
3. **検証データを見ずにラウンドを選ぶと、0.4〜0.8 点下がる**。
   - 上の 2 本（FedTT 1e-3・32、FedTT+ 5e-3・16）について、held-out で最高だったラウンドを選ぶと、FedTT 92.14、FedTT+ 92.44。
   - 論文の値は、検証データでラウンドとグリッドを選んだ楽観的な値である点に注意。
4. **送信量は §6 の計算どおり**。1 ラウンド・1 クライアントあたり、FedTT 236.9 KB、FedTT+ 71.3 KB（FedTT の 30 %）。

**要検討の点（論文と完全に同じ条件か）**
1. **評価に使ったデータ**：論文の表 8 では、MRPC の Dev は 367 件です。これは GLUE の訓練データ（3,668 件）から訓練用の 3,301 件を除いた件数で、GLUE の検証データ（408 件）ではありません。論文の「best validation」がどちらで測られたかは書かれていません。本再現は GLUE の検証データで比べました。367 件の held-out でも毎ラウンド評価しているので、ラウンドごとのログ（Google ドライブ）をこのリポジトリに入れれば、そちらでの最高値とも比べられます。
2. **どの 3,301 件を訓練に使ったか**：件数は同じですが、論文（FedPETuning）と同じ 3,301 件かはわかりません（本再現はシード 42 で無作為に選んだ）。
3. **ローカル学習の量**：論文には「local training epochs 1」（5.2 節）と「one local update per communication round」（付録 A.3）の 2 通りの書き方があります。本再現は 1 ローカルエポックと解釈しました（§3）。
4. **シードが 1 つ**：論文との差がシード間のばらつきに収まるかは、まだ測っていません。

## 6. 学習パラメータ数・送信量の照合（`python -m fedtt_repro.count`）

学習パラメータ数は、アーキテクチャの解釈（テンソルの形、アダプタの位置、何を学習するか）が論文と同じかどうかを、学習せずに確かめられる指標です。表 14 の KB は、丸めた個数 × 4 バイト / 1024 です（0.06M → 234 KB）。全行は `results/param_check.md` にあります。

| 設定 | 論文 | この実装（1 ラウンド） | 一致 |
|---|---|---|---|
| DeBERTa-base FedTT r5（表 1・7） | 0.06M / 234 KB | 60,634（0.061M）/ 237 KB | ✓ |
| DeBERTa-base FedTT+ r5（表 1） | 0.02M / 78 KB | 16,666〜21,466（平均 18,266、0.018M）/ 71 KB | ✓ |
| DeBERTa-base FedTT r2 / r10（表 7） | 0.03M / 0.17M | 29,362 / 167,794 | ✓ / ✓ |
| RoBERTa-base FedTT r5（表 2） | 0.06M | 60,634 | ✓ |
| RoBERTa-large FedTT r5、後ろ 6 層 / 後ろ 9 層（表 12） | 39K / 55K | 38,210 / 55,298（MNLI 56,323） | ほぼ（±1.3K） |
| RoBERTa-large FedTT+ r5、全 24 層（表 12・13） | 28K / 0.03M | 30,914〜50,114（平均 37,314） | **✗** |

**内訳（DeBERTa-base、2 クラス）**
- アダプタのコア：1 層 780 個 × 2（down・up）× 2 か所 × 12 ブロック = 37,440。
- アダプタのバイアス：(64 + 768) × 2 か所 × 12 ブロック = 19,968。
- 分類ヘッド：TT のコア 920 + バイアス 768 + 最後の 768×2 の層 1,538 = 3,226。
- FedTT は合計 **60,634**。FedTT+ は、各 TT 層で {G_1, G_r, G_5} の 280 個（r = 2, 4）または 380 個（r = 3）× 48 層 + 分類ヘッド 3,226 で、**16,666 / 21,466**。r = 2, 3, 4 の巡回で平均 **18,266**。

**一致したことからわかる、論文に書かれていない事実（隠れ 768）**
- アダプタは各ブロック 2 か所（注意の後ろ・MLP の後ろ）。
- FedTT はアダプタのバイアス（19,968 個）も学習する。FedTT+ はバイアスを学習しない（学習すると 0.04M になる）。
- 分類ヘッドの 768×768 は TT（[12,8,8,8,8,12]）、最後の 768×C は密な層のまま。
- LayerNorm は学習しない。

**RoBERTa-large（表 12）が合わない理由**
- 論文の表 10 に 1024 の形がないので、[8,8,16,8,8] を仮定しました。
- 1024×64 になる TT の形 5,869 通りを総当たりしても、39K・55K・28K を同時に満たすものはありません。
- そもそも 39K（6 層）と 55K（9 層）からは、1 層あたり約 5.3K・ヘッド約 7K が出ます。この 1 層あたりの量で全 24 層に FedTT+ を入れると、コアの約 4 割を送るだけでも 30K を超えます。
- 表 12 の FedTT+ の 28K は、「全層」「各ブロック 2 か所」「ランク 5」と同時には成り立ちません（論文内の不整合、§7 の 4）。

## 7. 論文の中の不整合・あいまいな点

1. **FedTT+ の r の選び方（Algorithm 2 の 3 行目）**：擬似コードは「mod(t, J−2) = r−1」で、r ∈ {1, …, J−2}（G_{J−1} を学習しない）。本文は「r ∈ {2, …, J−1}」。本実装の既定は本文どおり。擬似コードどおりの読み方も `plus_schedule="literal"` で回せる。
2. **3.2 節の例**：「768×768、コアの次元 [8,8,8,8,8,8]」は作れない（8⁶ = 512²）。
3. **表 10 の分類器の 2 行目**：「768×768 → [8,8,8,8,8,8,8,8]」は積が 4096²。LLaMA の行の誤記と思われる。
4. **表 12 の FedTT+ 28K**：§6 のとおり、ほかの数値と両立しない。
5. **表 3 のベースラインの列**：LoRA・FFA-LoRA・RoLoRA の行は、RoLoRA の表 2 と同じ数値で、**QQP と MNLI の列が入れ替わっている**（RoLoRA は SST-2・QNLI・MNLI・QQP の順）。4 タスクの平均は変わらないが、QQP・MNLI 個別の比較は別のタスク同士を比べていることになる（例：severe の「LoRA の QQP 58.96」は RoLoRA では MNLI の値）。
6. **表 6 と表 14 の総通信量**：MNLI の総送信量を、表 6 は FedTT 234 KB・FedTT+ 78 KB とする。表 14 では 468 KB・234 KB。表 6 の値は 1 ラウンド分の送信量そのもの。表 6 の「RoLoRA に対して ×0.37 / ×0.12」は、表 14 の数値では ×0.75 / ×0.375 になる。
7. **表 13 の severe の分割**：FedTT は 2 クラスで [0.05,0.95] と書き、「FFA-LoRA と全く同じ設定」とする。FFA-LoRA の原著は [0.1,0.9]。本実装は FedTT の記述を既定にし、`severe_ffa` も用意した。
8. **表 8 の「# Dev.」**：MRPC・SST-2 は FedPETuning の dev（訓練データから切り出したもの）、QNLI・QQP・MNLI は GLUE の検証データ（FedPETuning の test）の件数で、混ざっている。どちらで「best validation」を取ったのかが不明（§5 の要検討の点 1）。本実装は両方を記録し、GLUE の検証データでの最高値を主に、held-out で選んだ値を副に報告する。
9. **「local update」の意味**：表 1 は「local training epochs 1」と「one local update per round」の両方の書き方がある。表 14 の「2 ラウンドで 95 %」から、1 ローカルエポックと解釈した。表 3（20 updates）・表 13（10 updates）は、元論文（RoLoRA・FFA-LoRA）の設定からステップ数と解釈した。

## 8. 回し方

### Colab（GPU）
ノートブックは `reproduction/` に 2 つあります。どちらもコードを中に含んでいるので、**アップロードは不要**です。

| ノートブック | 中身 | 目安（A100） |
|---|---|---|
| `FedTT_MRPC_colab.ipynb` | 表 1 の MRPC。FedTT と FedTT+ を、まず学習率 1e-3・バッチ 32 で（ステップ A）、続いて論文と同じ 8 通りのグリッドで回す（ステップ B） | ステップ A（2 本）：約 30 分（実測）、全体（16 本）：3〜4 時間（見込み） |
| `FedTT_repro_colab.ipynb` | 全ステップ（表 1, 2, 3, 7, 13）を安い順に | 合計 100 時間以上（見込み） |

1. ノートブックを Colab で開きます（GitHub から開くか、ダウンロードして colab.research.google.com の「アップロード」）。
2. 「ランタイム → ランタイムのタイプを変更」で GPU を選びます。本再現は **A100 GPU・ハイメモリ**で回しました。L4 でも動きます。T4 でも動きますが、数倍遅くなります。
3. 「ランタイム → すべてのセルを実行」を押します。結果は Google ドライブの `MyDrive/FedTT_repro/results` に保存されます。
4. 途中で切れたら、もう一度「すべてのセルを実行」を押せば続きから進みます（終わったランは飛ばし、途中のランは 10 ラウンドごとのチェックポイントから再開）。
5. 最後の「結果（論文との比較）」のセルに、16 本の表と論文との比較が出ます。うまくいかないときは、いちばん下の「うまくいかないとき」のセルの出力を見てください。

### ローカル（CPU）
テスト、パラメータ数の照合、動作確認に使います。`reproduction/` フォルダで実行します（必要なパッケージは `requirements.txt`）。

```
python tests/test_core.py
python -m fedtt_repro.count --out ../results/param_check.md
python -m fedtt_repro.pipeline --suite smoke --out results_local --threads 10
python -m fedtt_repro.report --out results_local
```

`results_local/` は git に入れない作業用フォルダです。コードを直したら、`python tools/make_notebook.py` でノートブックを作り直します。
